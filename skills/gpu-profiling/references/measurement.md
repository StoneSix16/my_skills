# 算量、访存与算术强度

目标：给出每个关键算子的 FLOPs、bytes moved，以及两者的比值。这个比值决定它受算力还是带宽限制。

## 用形状普查，不要用 FLOPs 计数器

**形状普查**：包裹选定的子模块，只读输入输出的 `(shape, dtype)` 与调用次数，按签名计数。

为什么优于基于栈记录的 profiler：

- 只碰元数据，不碰数值，**可以在真实 workload 上常开**
- 基于栈记录的 profiler 会显著撑大前向（单次实测约 1.6×，只作量级参考，不是通用系数），绝对时间不可用
- 形状数量远小于算子数量，报告可读

代价：拿不到「每个算子的真实耗时分摊」。所以它与 L2 的算子级耗时是互补的，不是替代。

**采什么**：每个子模块的 `in/out` 形状与 dtype，以及**任何在时间上变化的量**（cache 占用、序列长度）。后者单独记，因为它不受形状不变性的保护。

## 先确认形状不变性

采一轮之后，第一件事是判断形状是否随迭代变化。做法：把每次迭代归约成一个「签名集合」（`标签 + in + out + dtype`），比较各次迭代的集合是否相同。

- **不变** → 一次采样可代表全部，算量算一次即可
- **有变** → 找出变化的那一维，它是算量增长的唯一来源

去重要按**形状**而不是按标签：同一个标签被两条执行路径以不同形状调用时，会合理地分成两行。看到行数比标签数多，先确认是这种合法的分裂，还是真的在漂移。

## Linear / GEMM

```
FLOPs   = 2 · b · L · K · N
bytes   = (K·N  +  b·L·K  +  b·L·N) · itemsize
          权重    输入      输出
```

`b·L` 是 batch 与序列长度的乘积（即「多少行」），`K`/`N` 是输入/输出特征维。

**算术强度** `AI = FLOPs / bytes`，单位 FLOP/byte。

关键观察：`b·L` 决定了 AI 的量级，与具体是哪个投影无关——权重项 `K·N` 在行数少时占绝对主导：

- **行数多**（`b·L` 与 `K` 同量级或更大）：AI 高，**算力受限**，提高 batch 才有意义
- **行数少**（`b·L` ≪ `K`）：AI 低，纯粹在**流带宽读权重**，FLOPs 减少不会转化为时间减少。此时合并/融合这个算子不会带来任何收益

这个区分是后面「理论算量 vs 实测时间」对不上的最常见原因。

**权重常驻是个假设**。若框架在每次调用前搬运权重（分片重建、参数重排），那笔搬运的代价不在这里，要单独计——否则会把它算进算子本身。

## Attention

attention 一般不是子模块，没有形状探针，但可由 query 长度 `L`、键值长度 `S` 与 `heads · head_dim` 推算：

```
FLOPs = 4 · b · L · S · (heads · head_dim)
```

其中 `heads` 与 `head_dim` 只以乘积出现——那个乘积就是 query 张量的最后一维。

**访存取决于是不是融合实现**（scores 是否物化）：

- **融合**（flash 类）：读 q、k、v，写输出 → `2 · b · (heads·head_dim) · (L + 2S)` 元素
- **非融合**：额外物化 scores `b · heads · L · S` 元素，写入再读出

两者算出的 AI 会差一倍，**报告里必须写明假设的是哪一种**。判断方法：看实际 kernel 名里有没有分块 attention 的实现，而不是看配置里写了什么。

若 K/V 来自一个被 gather 出来的池：

- gather 本身是一次**拷贝**（读 + 写各一遍），零 FLOP
- 它的访存与 `L` 无关、只随 `S` 增长
- 合并进 attention 的访存后，AI 在 `S → ∞` 时收敛到一个由 `L` 单独决定的上界

也就是说：**把缓存窗口开大不会让 attention 变得更有算力效率**。这个上界值得算出来写进结论。

## 必须带硬件参照

`AI` 本身没有判据意义。要与本机的

```
峰值算力 / 显存带宽
```

相比：AI 低于这个比值 → 带宽受限；高于 → 算力受限。同一个 AI 值在两张卡上可以有相反的结论，所以**不写参照的 AI 是不完整的结论**。

无法读取硬件计数器（`ncu` 不可用）时的替代判据：

- 耗时随规模的**斜率**：算量翻倍而耗时基本不变 → 带宽受限
- 同形状换不同实现（不同 attention 后端、不同 tile）→ 耗时变化大说明在受限区

## 输出：理论 vs 实测并排

最后给一张表，两列并排：理论算量、实测时间。**差距本身是结论**，不要只报其中一个。

差距的三个常见来源，按出现频率：

1. **与主变量无关的固定成本**。某个算子按固定长度的输入计算（如文本嵌入），不随主序列长度变化。它在小序列的那条路径上会不成比例地占大头——实测见过一条路径里，这类固定项占了该路径算量的 79%。
2. **带宽受限导致的非线性**。见上文 `b·L` 的讨论：算量差 2.5 倍，时间可能只差 1.3 倍。
3. **零 FLOP 的搬运**。gather、逐元素链、参数搬运在算量表里不存在，但占时间。

逐项对照时，把每个子模块的「算量比」与「时间比」并列。两个比值一致 → 该子模块在算力尺度上可比；差异大 → 上面三个来源之一，去指出来。
